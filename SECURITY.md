# Security Policy

## Supported versions

Проект экспериментальный. Исправления безопасности выпускаются только для
последнего состояния ветки `main`; фиксированного SLA нет.

## Сообщение об уязвимости

Не публикуйте токены, идентификаторы счетов, сделки или другие персональные
данные в issue. Используйте GitHub Private Vulnerability Reporting, если оно
доступно, либо свяжитесь с владельцем репозитория через его GitHub-профиль.

В сообщении укажите затронутую версию, воспроизводимый сценарий и влияние, но
замените все секреты и идентификаторы безопасными фиктивными значениями.

## Утечка секрета

Сначала отзовите или замените секрет у провайдера. Удаление строки или коммита
не делает уже раскрытый credential безопасным. Затем удалите причину утечки и
проверьте историю и дерево файлов сканером секретов.
